# Rinicake

Portfolio site for **Rinicake**.

A home page that shows the work first — a mosaic gallery, works in progress, a schedule of in-person
events, an about panel and a contact form — plus a separate `/portfolio` page holding everything,
filterable by medium.

## Tech stack

- **React 19** + **Vite 8**
- **react-router-dom** for the two routes
- **Tailwind CSS 4** for styling
- **lucide-react** for UI icons, plus local brand SVGs imported as components via `vite-plugin-svgr`
- **ESLint** (flat config) with the React Hooks and React Refresh plugins

## Design

The theme is defined once in `src/index.css` under `@theme`, using semantic names rather than raw
color values, so the palette can shift without touching component markup:

| Token | Role |
| --- | --- |
| `paper` | blush page background |
| `panel` | cards, forms, nav |
| `line` | hairline borders |
| `ink` | headings and body text |
| `muted` | secondary text |
| `meta` | tertiary text and mono labels |
| `slot` | label on an empty image slot |
| `berry` | raspberry accent (`berry-dark` for hover, `berry-soft` for tints) |

Type is **Playfair Display** for display copy, **Quicksand** (`font-ui`) for buttons and form labels,
and **Nunito** (`font-sans`) for body text, loaded from Google Fonts in `index.html`.

Two custom utilities live in `index.css` because utility classes can't express them:

- `hatch` — the diagonal fill behind an image slot with no artwork yet.
- `mosaic` — the six-column gallery grid. Tiles set their own `grid-column: span N` inline, and an
  inline style can't be overridden by a responsive utility, so the collapse to two columns under
  900px and one under 560px is defined there.

Shared button and pill classes are built by `btn()`, `chip()` and `TAG` in `src/lib/styles.js`, so an
`<a>`, a `<button>` and a router `<Link>` can all look like the same control.

Accessibility is handled as the components are built, not bolted on after: `prefers-reduced-motion`
collapses scroll behavior and transitions, interactive elements carry `focus-visible` rings, the
mobile menu toggle exposes `aria-expanded` and a state-aware `aria-label`, the portfolio filters
expose `aria-pressed`, and the contact form's result message is a `role="status"` live region.

## Getting started

Requires Node 18 or newer.

```bash
npm install
npm run dev        # start the local dev server
npm run build      # production build to dist/
npm run preview    # serve the production build locally
npm run lint       # run eslint

npm run new:piece  # scaffold a gallery piece
npm run new:event  # scaffold a show or convention
npm run images     # reprocess artwork (dev and build run this for you)
```

## Deploying

Set up on **Cloudflare Pages** with build command `npm run build` and output directory `dist`.
`.node-version` pins the build's Node.

`/portfolio` is a client-side route, so the host has to serve `index.html` for any path — otherwise a
direct visit or a refresh on that URL 404s. `public/_redirects` handles that and Vite copies it into
`dist/` on build.

## Editing site content

**Content lives as JSON under `content/`** — one file per piece, prototype and event, plus
`content/site.json` for everything that only exists once. `src/content-data/content.js` is no longer
data; it's the loader that assembles those files into the exports the components import. Adding work
never means opening a `.jsx` file.

There are three ways in, and they all write the same files:

| | |
| --- | --- |
| **From a phone or browser** | the admin UI at `/admin` — see below |
| **From a terminal** | `npm run new:piece` / `npm run new:event` |
| **By hand** | edit the JSON directly |

### What derives itself

Three things are computed, so don't hand-write them:

- **`ratio`** comes from the artwork's real pixel dimensions. Only set it on a piece with no image
  yet, where there are no pixels to measure.
- **`span`** — how many of the six mosaic columns a tile takes — comes from the image's shape:
  landscape gets 4, roughly square 3, portrait 2. Set it explicitly to override.
- **`past`** on an event is computed from its dates every time the page loads, so a show dims the day
  after it ends whether or not the site has been rebuilt since. There is no `past` field to set.

### Adding artwork

Drop the file in `public/images/originals/` (the admin UI and `npm run new:piece` both do this for
you) and put its **filename** in the record's `image` field. On the next build,
`scripts/build-images.mjs` generates avif and webp at up to four widths, measures the real
dimensions, and writes a blur placeholder into `src/content-data/images.json`.

Leave `image` empty and the tile renders a labelled hatch placeholder using `slot` instead — that's
what every entry currently does, so layout work can happen before the photos exist.

Give every real image an **`alt`**. It's the only field a screen reader has to go on.

### The collections

- **`content/work/`** — the home mosaic. `title`, `year`, `order`, `image`, `alt`, `slot`, optional
  `span` / `ratio` / `note`, and `tags` for the pills.
- **`content/pieces/`** — the `/portfolio` mosaic. Same shape, plus `medium` and `cat`. **`cat` must
  appear in `site.json` → `categories`** or no filter can reach the piece.
- **`content/upcoming/`** — works in progress. `status`, `dot` (hex colour of the status pill's
  indicator), `eta`, `medium`.
- **`content/events/`** — shows. `start` and optional `end` as ISO dates (`"2027-04-12"`), `place`,
  `detail`, `status`. The displayed date ("Apr 12—13") is formatted from those; `displayDate`
  overrides it if you need something the formatter can't express.

Within a collection, files are ordered by their **`order`** field, filename breaking ties. Events
ignore `order` and sort by date — soonest first, finished ones last.

### `content/site.json`

`creator` (name, tagline, blurb, Etsy URL, hero headline/lede, the commissions pill, and the
Web3Forms access key — a public client-side key, safe to commit), `socials`, `nav`, `contactTopics`,
`contactNotes`, `categories`, and `about`.

Two fields there are load-bearing:

- **`socials[].icon`** is a key, not a path — `content.js` maps it to an imported SVG component.
  A new icon needs an SVG in `src/assets/icons/` and a line in that map.
- **`nav[].id`** must match a section's `id` on the page, or the link scrolls nowhere.

Leave `about.stats` empty and the figure row isn't rendered.

## The admin UI

`/admin` runs [Sveltia CMS](https://github.com/sveltia/sveltia-cms) over the same files, committing
straight to GitHub. Its schema in `public/admin/config.yml` is Decap-compatible, so Decap is a
drop-in replacement if you ever want it.

**Try it locally first — this needs no auth setup at all:**

```bash
npx @sveltia/cms-proxy-server   # one terminal
npm run dev                     # another
# then open http://localhost:5173/admin/
```

That reads and writes your working tree directly. To use it from a phone against the real repo you
need GitHub auth: create a GitHub OAuth app, deploy the `sveltia-cms-auth` Cloudflare Worker as the
OAuth relay, and uncomment `base_url` in `config.yml`. (Netlify's hosted relay only works on Netlify,
which is why this piece has to be deployed.)

`backend.branch` in that config **must match the branch Cloudflare Pages deploys**, or edits will go
live nowhere.

One caveat worth knowing: a field that exists in the JSON but isn't declared in `config.yml` gets
dropped when that record is saved through the UI. If you add a field, add it to both.
